## 1. 인증

### 개요

카카오 소셜 로그인 기반 JWT 인증. 게스트 모드도 지원하여 로그인 없이 지도/매장/커뮤니티 조회 가능.

### 기능 목록

#### 1-1. 카카오 소셜 로그인

| 항목 | 내용 |
|------|------|
| 방식 | Authorization Code Flow (Implicit Flow 폐기) |
| 흐름 | 카카오 인가코드 발급 → `/oauth/callback` 리다이렉트 → 백엔드 `/auth/kakao`로 code 전달 → JWT 발급 |
| API | `POST /auth/kakao` — `{ code, redirectUri }` → `{ accessToken, refreshToken, user }` |
| 프론트 | `OAuthCallbackPage.jsx` — AuthGuard 바깥에서 콜백 처리 |

#### 1-2. JWT 토큰 관리

| 항목 | 내용 |
|------|------|
| Access Token | 유효기간 1시간, **메모리 저장** (페이지 새로고침 시 초기화) |
| Refresh Token | 유효기간 30일, localStorage(`auth-storage`) 저장 + DB 저장 |
| 자동 복원 | `AuthGuard`가 새로고침 후 refresh token으로 access token 재발급 (`POST /auth/refresh`) |
| 로그아웃 | `DELETE /auth/logout` — DB의 refresh token 무효화 |

#### 1-3. 게스트 모드

- 로그인 없이 지도, 매장 상세, 커뮤니티 목록/상세 조회 가능
- 인증이 필요한 액션(글쓰기, 좋아요, 식단기록 등)은 `AuthRequiredModal` 표시
- `useAuthRequired` 훅의 `requireAuth(fn)` 패턴으로 모든 인증 필요 액션에 적용

#### 1-4. 라우트 보호

- `/oauth/callback`을 제외한 모든 라우트는 `AuthGuard`로 보호
- `/admin/reports`는 `AuthGuard` + `AdminGuard` (role: ADMIN) 이중 보호

### 관련 파일

- `frontend/src/features/auth/AuthGuard.jsx`
- `frontend/src/features/auth/OAuthCallbackPage.jsx`
- `frontend/src/hooks/useAuthRequired.js`
- `frontend/src/store/useAuthStore.js`
- `backend/src/main/java/com/example/tdjmap/auth/`

## 2. 지도 & 매장 탐색

### 개요

OpenLayers 9 + VWorld WMTS 기반 지도에 인천 지역 174개 매장 마커를 표시. 지도 이동마다 bbox 기반으로 매장을 실시간 로드.

### 기능 목록

#### 2-1. 지도 렌더링

| 항목 | 내용 |
|------|------|
| 지도 엔진 | OpenLayers 9 |
| 타일 | VWorld WMTS (`VITE_VWORLD_API_KEY`) |
| 좌표계 | 내부: EPSG:3857 (Web Mercator), 외부 전달: EPSG:4326 (위경도) |
| 인스턴스 | `MapView.jsx`에서만 생성 → `useMapStore.setMapInstance()` 저장 |

#### 2-2. 매장 마커 실시간 로드

- `useMapStores` 훅이 `moveend` 이벤트마다 현재 bbox를 추출해 `GET /stores/search` 호출
- 빠른 이동/필터 변경 시 `AbortController`로 이전 요청 취소 (최신 응답만 반영)
- 마커 포맷: `{ id, name, address, category, lat, lon, brandLogoUrl, rating, grade, tags, nutrition, raw }`

#### 2-3. 마커 2단계 표시

| zoom | 표시 형태 | 색상 |
|------|-----------|------|
| < 15 | 원형 dot (w-4 h-4) | grade별: GREEN(`#4ADE80`) / YELLOW(`#FACC15`) / RED(`#F87171`) / 미등록(`#9CA3AF`) |
| ≥ 15 | 탄단지 박스 (80px) | 동일 grade 색상 체계 |

- grade `null` = 메뉴 정보 미등록 → 회색, 박스에 "정보 없음" 표시
- 마커 클릭 → `StoreCard` 표시

#### 2-4. 매장 키워드 검색

- `SearchOverlay`에서 텍스트 입력
- debounce 300ms → `storeFilters.keyword`로 백엔드 전달
- 백엔드: 매장명 / 주소 / 브랜드명 / 메뉴명 대상 LIKE 검색 (case-insensitive)
- API 파라미터: `q` (optional)

#### 2-5. 필터 시스템

**백엔드 필터:**
- `keyword`: 키워드 검색

**프론트 필터 (`MapPage.jsx` `visibleStores` useMemo):**
- **등급 칩**: GREEN(균형식) / YELLOW(일반식) / RED(주의식) — 카테고리 내 OR, 카테고리 간 AND
- **태그 칩**: 고단백 / 고지방 / 고탄수 / 저탄수
- **영양성분 슬라이더**: 탄수화물 / 단백질 / 지방 범위 설정 → `raw[key]` 숫자와 비교

`FilterBottomSheet`에서 UI 제공. `?` 버튼 → `FilterLegendSheet`로 등급 기준 설명.

**프론트 파생 태그 규칙** (백엔드 `nutritionTags` 없을 때):
- protein ≥ 25g → 고단백
- carbs ≤ 40g → 저탄수
- carbs ≥ 80g → 고탄수
- fat ≤ 10g → 저지방
- fat ≥ 25g → 고지방

#### 2-6. 내 위치 표시

- `useGeolocation`: 브라우저 위치 API로 현재 위치 획득 + 지도 이동 + 권한 처리
- `useLocationPixel`: 내 위치(latLon) → 지도 픽셀 좌표 변환 → 파란 점 마커 표시
- `postrender` 이벤트로 지도 이동 시 자동 업데이트

#### 2-7. 날씨 위젯

- `useWeather`: 기상청 API(`VITE_WEATHER_API_KEY`) 호출 → `useMapStore`에 weather/temperature/forecast 저장
- `WeatherWidget`: 현재 날씨/기온/예보 표시
- `WeatherCanvas`: `requestAnimationFrame` 기반 비/눈 애니메이션 (z-canvas: 35)
- 날씨 값: `sunny | partly-cloudy | cloudy | rain | snow`

#### 2-8. StoreCard (매장 미리보기)

마커 클릭 시 지도 위에 `z-ui(50)` 레이어로 표시.

| 표시 항목 | 내용 |
|-----------|------|
| 썸네일 | `brandLogoUrl` (브랜드 로고) |
| 기본 정보 | 매장명 / 주소 / 거리 / 도보시간 / 소모칼로리 / 별점 |
| 영양 정보 | 탄단지 NutritionCell + 태그 |
| 버튼 | "상세 보기" → `/map/store/:id` 이동, "길찾기" → RouteBottomSheet 열기 |

### 영양 등급 기준

| 등급 | 조건 |
|------|------|
| GREEN (균형식) | 탄수 35–55%, 단백 ≥30%, 지방 <25% |
| RED (주의식) | 탄수 ≥65% OR 지방 ≥35% OR 단백 <10% |
| YELLOW (일반식) | GREEN / RED 외 |

### 관련 파일

- `frontend/src/features/map/useMapStores.js`

- `frontend/src/features/map/useWeather.js`

## 3. 매장 상세

### 개요

매장 히어로 이미지, 기본 정보, 메뉴 목록, 리뷰를 탭으로 구성. URL: `/map/store/:id`.

### 기능 목록

#### 3-1. 매장 정보

- `GET /stores/{storeId}` — 매장명 / 주소 / 카테고리 / 이미지 / 별점 / 브랜드
- 히어로 이미지: `stores.imageUrl` 우선, 없으면 `brand.logoUrl` 폴백 (프론트)
- 거리/도보시간/소모칼로리: Haversine 직선거리 기준 (`useMapStore.latLon`과 비교)

#### 3-2. 메뉴 탭

- `GET /stores/{storeId}/menus` — 매장 전용 메뉴 + 브랜드 공통 메뉴(`store_id IS NULL`) 통합 반환
- **grade 필터 칩**: 전체 / 🟢 우수(GREEN) / 🟡 보통(YELLOW) / 🔴 주의(RED)
- **정렬 드롭다운**: 단백질순 / 탄수화물순 / 지방순 (`menu.raw[key]` 숫자 내림차순)
- 메뉴 카드 배경·테두리 색상 grade별 구분

메뉴 데이터 구조:
```
MenuItem: {
  id, name, kcal, carbs, protein, fat, sugar,
  grade: 'GREEN' | 'YELLOW' | 'RED' | null,
  tags: string[],
  nutrition: { carbs: '45g', protein: '20g', fat: '10g' },  // 표시용
  raw:       { carbs: 45,    protein: 20,    fat: 10    },   // 정렬용
}
```

#### 3-3. 리뷰 탭

**리뷰 목록:**
- `GET /stores/{storeId}/reviews` — 최신순, 닉네임 / 별점 / 내용 / 날짜 / 좋아요 수 / 내 좋아요 여부
- 비로그인 시 `liked: false` (서버에서 `getCurrentUserIdOrNull()`으로 처리)

**리뷰 작성:**
- `POST /stores/{storeId}/reviews` — JWT 필요, `{ star: 1–5, content: 최대 1000자 }`
- `ReviewComposer`: 별점 클릭 UI + textarea

**리뷰 좋아요 (하트):**
- `GET /stores/{storeId}/reviews/{reviewId}/likes` — 상태 조회
- `POST /stores/{storeId}/reviews/{reviewId}/likes` — 토글 (없으면 INSERT, 있으면 DELETE)
- `review_likes` 테이블: `UNIQUE(review_id, user_id)`로 중복 방지

### 관련 파일

- `frontend/src/features/map/MapStorePage.jsx`
- `frontend/src/features/map/useStoreDetail.js`
- `frontend/src/features/map/StoreDetailSections.jsx`

## 4. 경로 안내

### 개요

TMap API 연동. 도보/자전거/대중교통/차량 4가지 이동 수단의 경로를 지도 레이어로 표시.

### 기능 목록

#### 4-1. RouteBottomSheet

StoreCard "길찾기" 버튼 클릭 시 바텀시트 열림.

| 구성 | 역할 |
|------|------|
| `useRoute(store)` | TMap API 호출, mode 관리, 거리/시간/칼로리 계산 |
| `useRouteLayer(routeData, mode)` | 경로 GeoJSON → OpenLayers VectorLayer 추가/제거, 지도 뷰 fit |

#### 4-2. 이동 수단별 처리

| 수단 | 처리 방식 |
|------|-----------|
| 도보 (walk) | TMap 도보 API |
| 자전거 (bike) | TMap 도보 경로 가져와 자전거 속도(15km/h)로 시간 재계산 |
| 대중교통 (transit) | TMap transit API → leg별 수단(WALK/BUS/SUBWAY/TRAM) 분리 렌더링 |
| 차량 (car) | TMap 자동차 API |

#### 4-3. 소모칼로리 계산

```
칼로리 = MET × 사용자 체중(user.weight, 없으면 65kg) × 이동시간(시간 단위)
```

- Vite 프록시 `/api/tmap` → TMap API 서버 경유 (CORS 처리)

### 관련 파일

- `frontend/src/features/map/RouteBottomSheet.jsx`
- `frontend/src/features/map/useRoute.js`
- `frontend/src/features/map/useRouteLayer.js`

## 5. 커뮤니티

### 개요

익명 기반 탭 피드. 식단 공유 / 오운완 / 자유 게시판 3개 탭. 작성자 정보 미노출.

### 기능 목록

#### 5-1. 게시글 목록 (`/community`)

- `GET /posts?postType=식단 공유&page=0&size=20` — 인증 불필요
- 탭별 필터: `['식단 공유', '오운완', '자유 게시판']`
- 카드 표시: postType 배지 / 제목 / 내용 (2줄) / 좋아요 수 / 날짜
- 이미지 첨부 게시글: 내용 앞에 `📷 ` 이모지 인라인 표시
- 작성자 닉네임/authorId 미표시 (익명 게시판)

#### 5-2. 게시글 작성 (`/community/create`)

- JWT 필요 (비로그인 → `AuthRequiredModal`)
- `POST /posts` — `{ postType, title(max 100자), content, imageUrl? }`
- 이미지 첨부 흐름: `ImageUploader domain="posts"` → `POST /images/upload?domain=posts` → imageUrl 획득 → POST /posts body에 포함

#### 5-3. 게시글 상세 (`/community/post/:id`)

- `GET /posts/{postId}` — 인증 불필요
- 레이아웃: `PageLayout` 미사용, `div.h-dvh.flex.flex-col` 직접 구성
- 공유 버튼: `navigator.share()` 지원 시 Web Share API, 아니면 clipboard 복사

#### 5-4. 좋아요

- `GET /posts/{postId}/likes` — 상태 조회 (JWT 필요)
- `POST /posts/{postId}/likes` — 토글, `post_likes` 테이블 `UNIQUE(post_id, user_id)`로 중복 방지
- 비로그인 클릭 → `AuthRequiredModal`
- 실패 시 게시글 하단 에러 박스 표시

#### 5-5. 게시글 삭제

- `DELETE /posts/{postId}` — JWT 필요, 작성자 본인만 (타인 → 403)

### 관련 파일

- `frontend/src/features/community/CommunityPage.jsx`
- `frontend/src/features/community/PostCreatePage.jsx`
- `frontend/src/features/community/PostDetailPage.jsx`
- `backend/src/main/java/com/example/tdjmap/community/`

## 6. 식단 기록

### 기능 목록

#### 6-1. 식단 탭 (`/record` → 식단 탭)

| 표시 항목 | 내용 |
|-----------|------|
| 신장/체중 | `useAuthStore.user`에서 로드, ✏️ 버튼 → `/profile/body` 이동 |
| 칼로리 히어로 | 오늘 총 섭취 칼로리 (목표: 2000kcal 고정) |
| 매크로 바 | 탄수화물(목표 320g) / 단백질(목표 180g) / 지방(목표 75g) |
| 식단 목록 | 식사 유형별 카드 (아침/점심/저녁/간식) |

#### 6-2. 식단 상세 기록 페이지 (`/diet`)

- "기록하기" 버튼 → `/diet` 이동
- `ImageUploader domain="diet"` — 식단 사진 선택적 첨부

#### 6-3. API 연동

| 기능 | API |
|------|-----|
| 조회 | `GET /diet-logs?date=yyyy-MM-dd` |

| 삭제 | `DELETE /diet-logs/{logId}` — 본인만, 타인 → 403 |

- `menuId` optional — 챗봇 분석 메뉴와 연결 시 사용

#### 6-4. 식사 유형

`아침 | 점심 | 저녁 | 간식` — DB `diet_logs.meal_type` 컬럼 값과 일치

## 7. 운동 기록

### 개요

날짜별 운동 기록 조회/추가/삭제. 칼로리는 MET × 체중 × 시간으로 서버에서 자동 계산. JWT 필수.

### 기능 목록

#### 7-1. 운동 탭 (`/record` → 운동 탭)

| 표시 항목 | 내용 |
|-----------|------|
| 신장/체중 | 식단 탭과 동일 |
| 소비 칼로리 히어로 | 오늘 총 소비 칼로리 |
| 통계 그리드 | 총 운동 시간 / 종목 수 등 |
| 운동 목록 | `ExerciseActivityCard` — 종목 이모지 / 종목명 / 시간 / 칼로리 |

#### 7-2. 운동 추가 (`ExerciseAddModal`)

- "기록하기" 버튼 → `ExerciseAddModal` 열기
- 운동 종목 목록: `GET /exercise-types` — `{ typeId, typeName, metValue, iconUrl }`
- `POST /exercise-logs` — `{ typeId, title?, durationMin, memo? }`
- `caloriesBurned`는 보내지 않음, 서버가 `MET × 사용자 체중(없으면 65kg) × durationHour`로 계산

#### 7-3. 운동 종목 이모지 매핑

| 종목 | 이모지 |
|------|--------|
| 사이클 | 🚴 |

## 8. AI 챗봇

### 개요

텍스트 기반 메뉴 추천 + 이미지 영양성분 분석. 백엔드가 AI 서버(`192.168.110.63:3221`)로 프록시. 인증 불필요.

### 기능 목록

#### 8-1. 텍스트 메뉴 추천

```
사용자 입력 → POST /chatbot/recommend
  Body: { lat, lng, message, weather?, temperature? }
  → { reason, recommendations: Item[] }  (최대 3개)
  → AssistantBubble (reason + RecommendCard 목록)
```

- `latLon` 미설정 시 "지도 화면에서 현재 위치를 먼저 설정해 주세요." 안내
- `weather/temperature`는 `useMapStore`에서 자동 주입
- 추천 결과 후 식단 기록 확인 프롬프트 없음

**RecommendCard 클릭 → 지도 이동:**
```
카드 클릭 → useMapStore.setPendingStore({ id, name, lat, lon, grade, x, y })
→ navigate('/map')
→ MapPage: pendingStore 감지 → moveTo(x, y, 16) + selectStore + clearPendingStore
```

#### 8-2. 이미지 영양성분 분석

```
카메라 버튼 or 클립보드 붙여넣기 → pendingImage { file, previewUrl }
→ Canvas 리사이즈 (max 1024px, JPEG 85%) → base64 Data URL
→ POST /chatbot/analyze  { image: "data:image/jpeg;base64,..." }
→ { menuId?, menuName?, kcal?, carbs?, protein?, fat?, nutritionGrade?, nutritionTags?, reason }
→ AssistantBubble (reason + AnalysisCard)
```

- `hasMenu = data.menuId != null && data.menuName != null` → AnalysisCard 표시
- 미매칭 시 reason만 표시, AnalysisCard 없음
- AI 서버 장애 시 503 반환

#### 8-3. 식단 기록 추가 확인 (이미지 분석 후만)

```
분석 성공 + hasMenu → "식단 기록에 추가하시겠어요?" + 네/아니오 버튼
→ 네: POST /diet-logs 다건 병렬 호출 (menuId, foodName, logKcal 등 포함)
→ 아니오: "네 도움되셨길 바래요~"
→ 401 응답: "식단 기록을 추가하려면 로그인이 필요해요."
```

식사 유형 자동 결정:
```
06–11시 → 아침 / 11–15시 → 점심 / 18–22시 → 저녁 / 그 외 → 간식
```

#### 8-4. 이미지 입력 방법

- 카메라 아이콘 클릭 → `<input type="file" accept="image/*">`
- 클립보드 붙여넣기 (`onPaste`) — `image/*` 타입만 처리

### 영양 등급 표시

| YELLOW | 일반식 | `bg-yellow-50 text-yellow-700 border-yellow-200` |
| RED | 주의식 | `bg-red-50 text-red-700 border-red-200` |

## 9. 사용자 프로필

### 개요

카카오 로그인 후 자동 로드되는 사용자 정보 조회 및 수정. JWT 필수.

### 기능 목록

#### 9-1. 프로필 조회

- `GET /users/me` → `{ userId, nickname, role, height?, weight?, gender?, createdAt }`
- `AuthGuard` 로그인 직후 자동 호출 → `useAuthStore.user`에 저장
- 이후 컴포넌트는 별도 API 호출 없이 store에서 구독

#### 9-2. 프로필 수정 (`/profile/body`)

- `PUT /users/me` — `{ nickname?, height?, weight?, gender? }` (null 필드 무시 — 전달된 필드만 업데이트)
- `BodyProfilePage.jsx` — 신장(cm) / 체중(kg) / 성별(M|F) / 닉네임 수정 폼
- 저장 성공 → `useAuthStore.updateUser()`로 store 갱신
- 기록 탭 상단에 신장/체중 표시, ✏️ 클릭 → `/profile/body` 이동

#### 9-3. 신장/체중 활용처

| 기능 | 활용 |
|------|------|
| 운동 기록 칼로리 계산 | `MET × weight(없으면 65kg) × 시간` |
| 경로 안내 소모칼로리 | 동일 공식 |
| 기록 탭 UI | 신장/체중 표시 카드 |

## 10. 이미지 업로드

### 개요

도메인별 이미지를 서버에 업로드. UUID 파일명으로 저장, 정적 서빙. JWT 필수.

### 기능 목록

#### 10-1. 업로드 API

```
POST /images/upload?domain={domain}
Content-Type: multipart/form-data
→ { imageUrl: "http://localhost:8080/images/{domain}/{uuid}.ext" }
```

**지원 도메인:**
`stores | brands | menus | posts | diet | users | reviews | reports`

**제약 조건:**
- 허용 타입: `image/jpeg, image/png, image/webp, image/gif`
- 최대 크기: 10MB / 요청당 30MB
- 파일명: UUID 자동 생성

#### 10-2. 이미지 서빙

- `GET /images/{domain}/{uuid}.ext` — 인증 불필요
- 백엔드: `WebMvcConfig.java`에서 `/images/**` → `file:uploads/` 정적 서빙

#### 10-3. ImageUploader 컴포넌트

```jsx
<ImageUploader
  domain="posts"       // 업로드 도메인
  onChange={setUrl}    // 업로드 완료 URL 콜백 (null이면 제거)
  onFile={setFile}     // 파일 선택 즉시 콜백 (선택 prop)
  aspectRatio="4/3"    // CSS aspect-ratio (null이면 원본 비율)
  className="..."      // 추가 Tailwind 클래스
/>
```

- 파일 선택 즉시 ObjectURL 미리보기 → 업로드 완료 후 서버 URL로 교체
- 업로드 실패 → 미리보기 제거 + 에러 메시지

#### 10-4. 이미지 저장 위치 (서버)

```
backend/uploads/
├── stores/    매장 대표 이미지   (stores.image_url)
├── brands/    브랜드 로고        (brands.logo_url)
├── menus/     메뉴 이미지        (menus.menu_url)
├── posts/     게시글 첨부        (posts.image_url)
├── diet/      식단 사진          (diet_logs.img_url)
├── reports/   제보 첨부 이미지   (reports.image_url)
├── users/     프로필 사진        (예정)
└── reviews/   리뷰 첨부          (예정)
```

## 12. 관리자

### 개요

ADMIN role 사용자 전용 신고 관리 페이지. `AdminGuard`로 보호.

### 기능 목록

#### 12-1. 신고 목록 조회

```
GET /admin/reports
Header: Authorization: Bearer <jwt>  (role: ADMIN 필요)
→ [{ reportId, userId, userNickname, storeName, menuName,
     carbs?, protein?, fat?, imageUrl?, status, createdAt }]
```

- status: `PENDING | APPROVED | REJECTED`

#### 12-2. 신고 처리 상태 변경

```
PATCH /admin/reports/{reportId}/status
Body: { "status": "APPROVED" }   // APPROVED | REJECTED
→ 변경된 ReportAdminResponse
에러: 400 — 유효하지 않은 status 값
```

#### 12-3. 접근 제어

- `AdminGuard` — `useAuthStore.user.role === 'ADMIN'`인 경우만 진입 허용
- `AuthGuard` 내부에 중첩 적용 (이중 보호)
